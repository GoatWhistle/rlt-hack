# ML-постановка: восстановление состава закупки и рекомендация поставщиков

Документ описывает целевую ML-задачу и предлагаемый подход. Модели ещё не обучены, качество не измерено.

## Цель

По данным извещения определить предполагаемые товары, работы или услуги, найти подходящих поставщиков и ранжировать их для закупки целиком. Дополнительно — выбрать прогнозного победителя среди найденных кандидатов.

Задача состоит из трёх этапов:

1. Определение состава закупки и классификация позиций по ОКПД2.
2. Подбор потенциально подходящих поставщиков.
3. Ранжирование поставщиков и прогноз победителя лота.

Историческая победа — наблюдаемый результат закупки, а не доказательство лучшего качества или надёжности поставщика. Релевантность поставщика и прогноз победителя оцениваются отдельно.

## Данные

Исходный архив содержит три связанные таблицы:

| Таблица | Объём | Используемые сведения |
|---|---:|---|
| Извещения | 604 452 строки | `lot_id`, `procedure_name`, `subject`, `publish_date`, `start_price`, `customer_inn`, `is_smp`, источник |
| Поставщики | 1 010 138 строк | `lot_id`, `supplier_inn`, `supplier_kpp`, `is_winner` |
| ТРУ | 2 971 651 строка | `lot_id`, `product_name`, `okpd2_code` |

Связь таблиц — по `lot_id`. Период публикаций: 2024–2025 годы. В данных 44 199 уникальных ИНН поставщиков.

Свойства данных, существенные для обучения:

- У 32 104 поставщиков не больше пяти записей об участии; у 16 004 — одна. Модель должна работать с небольшой историей.
- 323 791 лот содержит одну позицию ТРУ. Такие лоты подходят для первоначального обучения связи между предметом закупки и поставщиком.
- Встречаются большие многопозиционные лоты. Нельзя считать каждую позицию независимым подтверждением специализации каждого участника.
- В АИС ГЗ почти всегда представлен один поставщик-победитель. Эти данные не считаются полной историей конкуренции.
- В ЭМ несколько записей о поставщиках есть у 159 084 лотов. Эта часть полезнее для обучения сравнению участников.
- В архиве нет цен предложений, фактических цен контрактов, качества исполнения, количества и цены единицы товара, дат подачи заявок и определения победителей.

## Вход и результат ML

Вход — запись извещения. Основной текстовый признак — `procedure_name`; `subject` и остальные поля используются, если доступны во входных данных.

Для каждого лота модели возвращают:

- список предполагаемых позиций с названиями, кодами ОКПД2 и оценкой уверенности;
- список поставщиков-кандидатов с оценками соответствия;
- ранжированный список поставщиков на весь лот;
- прогнозного победителя либо признак недостаточности данных.

Победитель в исходной разметке относится к лоту, а не к отдельной позиции ТРУ. Рекомендации по товарам объединяются перед выбором лидера лота.

## Задача 1. Определение состава закупки

**Вход:** название и, при наличии, предмет закупки.

**Цель:** получить набор пар `product_name` / `okpd2_code`.

Обучающие примеры формируются по связи извещений с ТРУ. Возможный подход — извлечение явно названных позиций, поиск близких товарных описаний и многометочная классификация ОКПД2.

Необходимо различать:

- позиции, явно указанные в тексте;
- позиции, предполагаемые по историческим аналогам;
- категорию закупки, для которой конкретный состав неизвестен.

По формулировке «Поставка хозяйственных товаров» невозможно однозначно восстановить конкретную номенклатуру. В таком случае допустимы несколько гипотез или рекомендация на уровне категории. Предположения не считаются установленными фактами.

Этот этап — зона ответственности модуля определения товаров и классификации. Для рекомендателя обязательны `lot_id`, описание позиции, ОКПД2 при наличии и признак уверенности/происхождения позиции.

## Задача 2. Подбор поставщиков

### Представление поставщика

Профиль строится по предшествующей истории: предметам закупок, позициям ТРУ, категориям, участию и победам. Дополнительные описания и каталоги используются при наличии подтверждённого источника и времени получения.

Для компании формируется несколько карточек направлений деятельности. Например, поставка канцелярии и обслуживание компьютеров представляются отдельно. Повторяющиеся описания удаляются, количество исторических примеров в карточке ограничивается.

Для компаний без истории профиль может строиться по описанию деятельности или каталогу. Если нет ни истории, ни описаний, оценить предметную релевантность по одному ИНН невозможно.

### Модель

Основной вариант — дообученный текстовый bi-encoder:

- энкодер запроса получает описание товара, услуги или закупки;
- энкодер карточки получает описание направления деятельности поставщика;
- близость векторов определяет семантическое соответствие.

Начальная реализация использует предобученный многоязычный энкодер с общими весами для обеих сторон. Отдельные веса и дополнительные признаки рассматриваются как эксперименты.

Кандидаты собираются поиском по векторам и точным словам/обозначениям. Затем карточки объединяются по ИНН поставщика. Стартовый размер пула — 100–300 поставщиков на лот; окончательное значение определяется по полноте поиска.

### Обучающие примеры

Положительный сигнал — участие поставщика в соответствующем лоте. Для первоначальной выборки приоритетны однопозиционные закупки. Проигравшие участники тоже считаются потенциально релевантными.

Обучение контрастивное: близость подходящих пар увеличивается относительно примеров для сравнения. Для одного запроса допускаются несколько положительных поставщиков.

Отрицательные примеры включают другие направления деятельности и проверенные смысловые несоответствия. Тематически близкие поставщики без участия — только слабые отрицательные примеры: неучастие не доказывает нерелевантность.

Из отрицательных исключаются известные положительные пары. Ограничивается вклад повторяющихся закупок и наиболее активных компаний.

### Многопозиционные лоты

Для каждого кандидата вычисляются соответствие отдельным позициям, доля покрытых позиций и наличие опыта похожих комплексных закупок. Неподтверждённые позиции сохраняются как неопределённость. Простая сумма сходств не должна давать преимущество только за количество карточек компании.

## Задача 3. Ранжирование и прогноз победителя

Основной вариант — CatBoost Ranker.

**Обучающая группа:** исторический лот и его фактически представленные участники.

**Целевая переменная:** `is_winner`. Лоты с одним участником не дают пар для обучения предпочтению победителя перед конкурентами. Лоты без победителя и с несколькими отметками победы анализируются отдельно; спорные случаи исключаются из начального обучения прогнозу единственного победителя.

Признаки пары «лот — поставщик»:

| Группа | Примеры |
|---|---|
| Соответствие | Семантическая близость, совпадение ОКПД2 и точных обозначений, покрытие позиций |
| Релевантный опыт | Предыдущие участия и победы в категории, количество похожих лотов |
| Масштаб | Соответствие начальной цены диапазону прошлых закупок |
| Заказчик | Предшествующий опыт с данным заказчиком |
| Актуальность | Давность релевантного участия |
| Неопределённость | Объём истории, неполнота профиля, уверенность определения товаров |

Доли побед сглаживаются с учётом объёма истории. Начальная цена используется только как приблизительный показатель масштаба заказа.

На применении модель получает кандидатов от этапа подбора. Это отличается от обучения среди фактических участников. Поэтому качество проверяется на полной цепочке, а балл модели не интерпретируется как откалиброванная вероятность победы.

Если целью становится именно полезность рекомендации, отдельный ранжировщик обучается на экспертных оценках соответствия. Метки исторической победы не заменяют такую разметку.

## Предотвращение утечки данных

- Целевой лот и его результаты не включаются в профиль поставщика для соответствующего примера.
- Все исторические агрегаты рассчитываются на момент до целевой закупки.
- Нормализация и объединение строк не должны размножать факты участия при соединении с многопозиционными ТРУ.
- Разбиение выполняется по времени и лотам. Варианты одного запроса остаются в одном блоке.
- Будущие сведения о компании не используются в историческом тесте.
- При обучении на предсказанных товарах используются предсказания модели, не обучавшейся на соответствующем блоке.

В архиве отсутствует время, когда сведения об участии и победе стали известны. Разделение по дате публикации и временной зазор дают приближённый тест, но не гарантируют полного отсутствия временной утечки. Это ограничение фиксируется в отчёте.

## Оценка качества

Базовая схема: начало 2024 года — накопление истории, последующая часть 2024 года — обучение, первая половина 2025 года — валидация, вторая — итоговый тест. Точные границы и зазор фиксируются до подбора гиперпараметров.

Оцениваются два режима:

1. Рекомендатель получает настоящие ТРУ из архива — оценка при известном составе заказа.
2. Рекомендатель получает позиции, предсказанные из извещения — оценка полной цепочки.

| Задача | Метрики |
|---|---|
| Определение товаров | Precision/Recall/F1 по согласованным позициям и ОКПД2, отдельная оценка общих формулировок |
| Подбор поставщиков | Recall@100 по известным участникам, попадание исторического победителя в кандидаты |
| Прогноз победителя | Hit@1, Hit@5, MRR на лотах с однозначной разметкой |
| Релевантность рекомендаций | NDCG@10 и Precision@5 по экспертной разметке |

Исторические метрики отражают восстановление наблюдавшихся участников и победителей. Они не доказывают нерелевантность других рекомендованных компаний.

Для экспертной оценки нужен отдельный набор реальных запросов с оценками поставщиков по соответствию и подтверждениям. Качество измеряется отдельно для компаний с малой историей, новых компаний, редких категорий и многопозиционных лотов.

Новые поставщики оцениваются только при наличии доступного на момент запроса описания. Если положительный поставщик отсутствует в доступной базе кандидатов, это учитывается как ограничение покрытия; такие случаи нельзя молча исключать из общей оценки.

## Эксперименты и результат работы

Сравниваем последовательно:

1. Подбор по словам и ОКПД2.
2. Поиск с готовым текстовым энкодером.
3. Дообученный энкодер.
4. Несколько направлений деятельности на поставщика вместо одного профиля.
5. Добавление ранжировщика.
6. Полную цепочку с предсказанными товарами.

Ожидаемые результаты работы: воспроизводимая подготовка выборок, обученные модели, зафиксированные временные разбиения, таблица метрик, анализ ошибок и предсказания на отложенном наборе.

Основная гипотеза: дообучение на истории закупок и представление поставщика несколькими направлениями деятельности улучшают подбор по сравнению с базовым текстовым поиском. Отдельно проверяется, помогает ли история участия ранжировать кандидатов и прогнозировать победителя при неполном описании заказа.
