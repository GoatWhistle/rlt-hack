# Уточнение организаторов из обсуждения команды

Получено от пользователя 2026-10-01. Пересказ сопоставлен с [презентацией](../task/docs/presentation.md), подтянутой из репозитория команды.

- Решение может использовать готовые модели, поиск, RAG, агента или обучаемые компоненты. Обязательное обучение собственной модели не заявлено.
- Во время применения не обращаться к внешним LLM API. Допускаются самостоятельно размещённые модели, в том числе на отдельном собственном сервере.
- Качество должно подтверждаться метриками. Сложность решения должна быть обоснована.
- Нужна расширяемая архитектура: возможность подключать другие компоненты.

Презентация явно запрещает **внешние API нейронных сетей**, но отдельно требует механизм поиска в **открытых источниках** и обогащения контрагентов. Это не общий запрет интернета: подготовка внешних проверяемых сведений и внешний neural API — разные операции.

Приоритеты официальной оценки: работоспособность 30, качество рекомендаций 25, обогащение/новые компании/классификация ролей 25, объяснимость 10, UX 10. Исторический победитель — диагностическая метрика, а не основная бизнес-цель. После выбора поиска нужен отдельный этап обогащения с источниками, временем получения и доказательствами ролей; одной историей участия 25 баллов за обогащение не закрыть.

Рабочая интерпретация: загрузка библиотек и готовых весов выполняется отдельно при подготовке; обучение и применение используют локальный кеш и данные. Скачивание готовой модели не заменяет проверку её качества на нашей задаче.

Последовательность экспериментов:

1. Поиск по словам/ОКПД2.
2. Готовые Qwen3-Embedding-0.6B, BGE-M3 и E5 на одинаковой временной выборке.
3. Гибридный поиск и обучение CatBoost; отдельно качество кандидатов и прогноз победителя.
4. Дообучение энкодера через LoRA, если готовая модель не даёт достаточного качества.
5. Нейронный reranker, граф и агент — дополнительные эксперименты, если измерен полезный эффект.

Прямой поиск по тексту извещения не называется полной реализацией восстановления ТРУ. Граф связей по лотам и ИНН уже представлен связанными таблицами; необходимость отдельной графовой БД проверяется задачей, а не наличием такого инструмента.
