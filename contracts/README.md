# Контракт HTTP API

Примеры `*.example.json` фиксируют форму ответов и запросов. Контрактные тесты
backend (`backend/tests/controller/test_contracts.py`, `test_upload_api.py`,
`test_error_codes.py`) прогоняют их через DTO, а фронтенд разбирает каждый пример
своими парсерами (`frontend/tests/entities/*`). `error-codes.json` — полный список
кодов ошибок с HTTP-статусами; у каждого кода есть текст в словарях фронтенда
`errors.json` (ru и en).

## Совместимые изменения

- Новое необязательное поле ответа. Парсер фронтенда игнорирует незнакомые поля,
  а новое поле читает как необязательное.
- Новое значение в списках кодов `warnings`, `highlights`, `checkReasons`.
  Фронтенд пропускает незнакомые коды в этих списках и разбирает остальное.
- Новый код ошибки. Фронтенд показывает текст по HTTP-статусу, пока в словаре нет
  текста по коду; код добавляется в `error-codes.json` и словари в том же
  изменении.

## Несовместимые изменения

- Удаление или переименование поля, смена типа, новое обязательное поле.
- Новое значение одиночного перечисления (`status`, `role`, `basis`, `origin`,
  `kind`, `outcome`): фронтенд отклоняет ответ с незнакомым значением.

Несовместимое изменение выкладывается так: сначала фронтенд, который понимает
старую и новую форму, затем backend. Сохранённые результаты читаются по своей
версии: архив поиска и результаты закупок несут `payload_version`, декодер
принимает перечисленные версии и отказывает в остальных (`CorruptRecordError`,
ответ 500). Новая версия payload добавляет ветку чтения старой, а не
переписывает сохранённые записи.

## Кэширование

`GET /api/searches/{id}`, `GET /api/uploads/{id}` и
`GET /api/uploads/{id}/summary` отдают слабый `ETag`; повтор с `If-None-Match`
даёт 304. Тег включает версию представления: при изменении формы ответа она
повышается в контроллере (`VIEW_VERSION`, `DETAIL_VERSION`).
