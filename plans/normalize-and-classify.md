## Чистка схемы и единый ключ идентичности

- [x] Убрать поля, которые никто не заполняет (миграция 0006): `legal_status` у
      компании, `enabled` у источника, `delivery_regions` и `role_evidence_url`
      у предложения. `seller_evidence_url` переименован в `evidence_url`.
- [x] Свести валюту к коду ISO: источники писали рубль и как `RUR` (1,973), и
      как `RUB` (644). Теперь в хранилище один код.
- [x] Единое правило ключа источника в `identity.external_id` и команда
      `reidentify` для перевода сохранённых позиций с сохранением истории.

`ownership_status` и `ownership_evidence_url` у источника в чистку не вошли,
хотя по данным выглядели мёртвыми: через них адаптеры фида и сайта заполняют
`evidence_url`, где 2,663 значения не повторяют адрес карточки. Поля живые,
просто контейнер их пока не заполняет.

`role_evidence_url` убран после проверки на данных: ни одного значения, которого
нет либо в `url`, либо в соседнем `evidence_url`.

Перевод ключей на живых данных: 9,386 позиций, сменили ключ 4,700 (каталоги
texzakaz и optkatalog, где ключ собирался из адреса и названия), слилась одна
позиция — две записи отличались только пунктуацией названия. Время первой
встречи сохранено, повторный запуск команды меняет ноль записей. Длина ключа у
texzakaz упала с 644 до 39 символов в максимуме, суммарный объём ключей — с 716
до 306 КБ.

## Измерения 1 октября 2026 года

База ClickHouse 26.9.7 пересоздана с нуля: четыре миграции, затем полный обход
всех восьми источников через контейнер (`docker compose run sync-job sync`,
11 мин 15 с, лимит 500 карточек на источник). Все источники завершились со
статусом `success`. Нормализация и классификация выполнены самим обходом,
правила `normalizer-1` / `classifier-1`; отдельный пересчёт всего хранилища
командой `normalize` занимает около 5 с.

| Показатель | Значение |
| --- | --- |
| источников / компаний / позиций | 8 / 1,501 / 9,386 |
| нормализовано | 9,386 (100%) |
| с кодом ОКПД2 и рубрикой | 5,221 (55.6%) |
| из них словарём головных слов | 4,450 (47.4%) |
| из них картой разделов каталога | 771 (8.2%) |
| без кода (метод `none`) | 4,165 (44.4%) |
| с единицей ОКЕИ и ценой за базовую единицу | 1,973 (21.0%) |
| с брендом | 4,099 (43.7%) |
| с артикулом | 1,085 (11.6%) |
| с каноническими характеристиками | 2,607 (27.8%) |

Распределение рубрик на классифицированных: одежда и обувь 1,143, инструмент
1,057, металлоизделия 558, оборудование 384, электроника 345, электрооборудование
303, пластик 257, стройматериалы 195, транспорт 184, мебель 173, текстиль 131,
остальные рубрики меньше ста позиций каждая.

Проверка данных после прогона: 17 инвариантов целостности равны нулю — нет
позиций без нормализации, кода без рубрики или уровня, метода без кода и кода
без метода, неверных форматов кода, уверенности вне диапазона 0–1,
отрицательных цен, цены за единицу без самой единицы, перевёрнутых дат и
адресов не по http. Уверенность по каналам ровно одна на канал: `lexicon` 0.6,
`source_map` 0.7, `none` 0. Версия правил в хранилище одна. У 1,054 компаний из
1,501 есть ИНН, и все они проходят проверку формата.

Наблюдения прогона:

- Название из одного рекламного слова («ОПТОМ») обнуляло ядро и ключ склейки.
  Исправлено: при пустом результате чистки ядром остаётся очищенное исходное
  название. На проверку добавлен отдельный случай.
- Excel портит числа в обе стороны: кроме «янв.79» встретилось «10.июн»
  (исходное «10.6») — 168 значений характеристик. Лечение дополнено обратным
  порядком, после пересчёта таких значений не осталось.
- Бренд и артикул, найденные разбором в названии, не попадали в колонки
  таблицы: артикул был у 1,085 позиций, хотя разбор находил его у 3,175.
  Теперь в колонку пишется лучшее известное значение, как и для кода ОКПД2.
- У kdom.ru из 500 позиций классифицированы 9. Причина не в классификаторе:
  источник публикует вместо предмета название рисунка («Бордовый», «Лучшей
  маме», «Настоящий чемпион»). Предмета в названии нет, и классификатор
  правильно отказывается. Лечится на стороне парсера — полным путём разделов.

Выбор окна поиска головного слова проверен на тех же названиях: 2 слова — 46.4%
покрытия, 3 — 50.8%, 4 — 52.5%, 6 — 54.3%, без ограничения — 56.7% (здесь
только словарный канал, без карты каталогов). Оставлено окно в 4 слова: всё,
что добавляют более широкие окна, — это слова из хвоста описания, которые
предметом не являются («картридж» в названии инсулина, «клещи» в спрее от
клещей, «прокат» в перечне услуг павильона).

## Что не сделано и чего ждать

- Канал `archive` реализован и покрыт тестом, но в ClickHouse архив закупок ещё
  не загружен: `procurement_items` пуста, поэтому на текущих данных канал не
  даёт ни одного кода. После загрузки ТРУ он станет основным для товарных
  позиций.
- Канал `reference` работает по справочнику верхних уровней ОКПД2: 88 классов и
  73 группы. Полная официальная выгрузка заменяет файл без изменений кода.
- Карта разделов каталогов заполнена для `yml_feed`: 99 разделов из 167
  покрывают 38.1% позиций источника. Остальные разделы — обрывки крошек без
  родителя («Стальные», «Плоские») и бренд «СИБРТЕХ»; они намеренно не
  отображены. Полный путь крошек парсеры пока не отдают.
- Единица измерения известна только там, где источник публикует её сам: у
  остальных источников поля нет, и выдумывать её нормализатор не будет.
- Склейка дублей ограничена ключом «бренд и артикул» или ядром названия;
  нечёткого сопоставления внутри блоков-кандидатов пока нет.
- Компании не обогащены по реестру: ОКВЭД, направления и роли не заполняются.
- Отчёт о покрытии считается по всему хранилищу; разреза по источникам в команде
  `coverage` пока нет.
