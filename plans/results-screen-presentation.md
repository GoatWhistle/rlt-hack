# Улучшить подачу рекомендаций на экране результатов

Статус: выполнено 01.10.2026. Палитра не менялась: компоновка сделана в текущих токенах, индиго и янтарный не применялись до согласования.

## Цель

Доработать второй экран (`/results`), чтобы пользователь сразу понимал, кого рекомендует система, для каких товаров, на основании каких данных и что нужно уточнить. Сохранить цепочку «Запрос → товары → компании → основания».

Контекст: обсуждение скриншота экрана «Поставка продуктов питания» от 01.10.2026. Сейчас крупная верхняя сводка повторяет содержимое, списки занимают много места, а источники и ограничения оказываются ниже первого экрана.

Связанные документы: `frontend/DESIGN.md`, `plans/frontend.md`.

## Изменения

- [x] Сжать шапку: название закупки, лот и имя файла; рядом действие «Скачать CSV». Под ними компактная сводка количества товаров, кандидатов и компаний, требующих проверки.
- [x] Заменить четыре крупные карточки этапов небольшим индикатором цепочки. Убрать повтор названия закупки и выбранной компании из сводки.
- [x] Перераспределить ширину колонок: ориентир 25% для товаров, 30% для компаний, 45% для оснований. Проверить читаемость на ноутбуке; на узких экранах переходить к последовательному просмотру без сжатия трёх колонок.
- [x] Уплотнить строки товаров: название, короткая подпись происхождения и ОКПД2. Полное объяснение происхождения раскрывать по нажатию. Предположенные позиции явно помечать «Нужно подтвердить», уточнённые пользователем отличать подписью и иконкой.
- [x] Уплотнить карточки компаний: место в списке, название, роль, совпадение по товарам и число похожих закупок. ИНН перенести в подробности. Выбранную компанию выделить рамкой и поверхностью.
- [x] Вместо общего «Проверить» показывать конкретную причину, когда она известна, например «Не подтверждён ассортимент». Не придумывать причину при отсутствии данных.
- [x] В начале правой панели разместить короткий вывод «Почему рекомендуем», затем блоки «Соответствие товарам», «Опыт закупок», «Что уточнить».
- [x] Источники показывать рядом с подтверждаемыми утверждениями: ссылка, тип источника и дата проверки при наличии. Длинные списки и подробности раскрывать по запросу.
- [x] Различать сведения из каталога, фактическое наличие и предположение системы. Исторические участия и победы не выдавать за гарантию будущей поставки или победы.

## Визуальная система

Сохранить светлые поверхности, тонкие разделители и выразительную иерархию текста. Главный акцент — панель объяснения; повторяющиеся метки и метаданные сделать спокойнее. Статусы различать текстом и формой, а не только цветом.

В обсуждении предложены индиго для выбора и действий и янтарный для уточнений. Это расходится с текущей нейтральной палитрой `frontend/DESIGN.md`, где цветные заливки запрещены. Перед применением новой палитры отдельно согласовать и обновить дизайн-систему; изменения компоновки выполнять в существующих токенах.

## Критерии готовности

- [x] При размере окна 1440×900 без прокрутки видны выбранная компания, краткое основание рекомендации, ссылка на подтверждение и существенное уточнение, если оно есть.
- [x] Переключение компании обновляет объяснение и сохраняет понятное выделение выбранного кандидата.
- [x] Длинные названия, отсутствующие источники и неподтверждённые товары не ломают компоновку и не скрывают ограничения.
- [x] Известно, что означает «6 из 7 позиций»: совпадение по имеющимся сведениям, а не подтверждённое наличие на складе.
- [x] Проверены русская и английская версии, навигация с клавиатуры и узкий экран; основной текст остаётся читаемым.
- [x] После реализации проходят `npm run verify` и относящиеся к экрану e2e-проверки; приложены скриншоты результата на настольном и узком экранах.

## Результат

- Шапка: лот и файл, название закупки, «Скачать CSV»; строка итогов и компактный индикатор цепочки (`pages/results/result-header`, `chain-indicator`).
- Колонки 25/30/45 % на широком экране, одна колонка до 64rem; на узком экране выбор компании прокручивает к основаниям.
- Товары раскрываются по нажатию (`details`) и показывают полное объяснение происхождения.
- Модель ответа расширена: `summary`, `checkReason`, `matches` с основанием `stock`/`catalog`/`inferred` и источником, `wins`, `purchases` с источниками (`entities/recommendation/model.ts`). Источник необязателен — отсутствие показывается подписью «Источник не указан».
- Панель: «Почему рекомендуем» (или «Почему нужна проверка») с главным уточнением, «Соответствие товарам», «Опыт закупок» с оговоркой про будущие поставки, «Что уточнить». Длинные списки сворачиваются.
- Проверки: `npm run verify` (135 тестов), Playwright 18/18, включая видимость ключевого содержимого при 1440×900, клавиатуру, axe на десктопе и мобильном.
