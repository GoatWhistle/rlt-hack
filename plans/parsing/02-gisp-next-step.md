# ГИСП: проверить остановленный сбор

Статус: офлайн-проверка завершена 1 октября 2026 года; после отдельного
указания владельца полный сбор возобновлён и завершён. Итог — в
[основном плане](02-gisp.md).

## Задача

Проверить уже сохранённые вне Git данные ГИСП и определить, можно ли безопасно
продолжить полный обход. Не считать частичную продукцию полным снимком.

## Входные данные

- `/tmp/gisp-organizations.jsonl` — 8 118 организаций; при сборе проверены
  число строк и повтор первой страницы.
- `/tmp/gisp-products.jsonl.partial` и контрольная точка рядом — 262 400 из
  1 084 900 строк продукции на момент остановки. Процессы сбора остановлены.
- Незакоммиченные изменения адаптера в `feat/gisp-provider`: исправление
  идентификатора версии с учётом документа заключения и чтение локального
  снимка. Их ещё надо проверить на всём объёме.

## Проверка сохранённого фрагмента

Локальный разбор завершён за 11,7 секунды; пик RSS процесса — 128 МиБ.
Размер файла 467 696 124 байта совпадает с контрольной точкой. Прочитаны
8 118 организаций с 8 118 разными ID и 262 400 строк продукции (2 624
полные страницы по 100 строк). Ошибок JSON и формата, повторов строк и
неполных страниц нет. Контрольная точка содержит то же число строк и следующий
offset 262 400.

При первом проходе найдены 1 588 конфликтов ID: версии одного номера имели
одинаковый документ заключения, но разные ссылки на выписку и даты прекращения.
Идентификатор дополнен ссылкой `_product_writeout_url`, добавлен тест двух
таких версий. Повторный полный проход: 262 400 уникальных ID, конфликтов нет.
`gisp_api.py` и Ruff для адаптера прошли.

Из 262 400 строк 200 734 ссылаются на компанию из отдельного перечня
организаций. Оставшиеся 61 666 строк относятся к 1 727 другим ID компаний;
адаптер формирует для них `Supplier` из самой записи продукции, поэтому
связь предложения с компанией сохраняется. Это не признак потери строк.

Решение: **можно продолжать с контрольной точки** после согласования.
Осталось 822 500 строк, около 76 % перечня. По наблюдавшейся скорости
прошлого сбора (около 240 000 строк за 10 минут) это ориентировочно
35 минут работы; число строк источника и первая страница должны совпасть с
контрольной точкой при возобновлении. Затем нужно проверить весь полный снимок
и сформировать `SupplierPackage` без передачи в ClickHouse.

Готовность этого шага: отчёт по 262 400 строкам с решением «можно продолжать»
или конкретной причиной перезапуска. Полная цель из [плана ГИСП](02-gisp.md)
закрывается только после обхода всей продукции, сверки полноты и проверки
готового `SupplierPackage`. До этого ничего не записывать в ClickHouse.
