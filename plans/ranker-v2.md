# Ранжирование Qwen 4B и объяснения рекомендаций

Статус: модель принята на независимом test и подключена к рабочему поиску, 2026-10-02.

## Требования владельца

Только Qwen3-Embedding-4B: локальный кеш на предоставленном GPU для экспериментов;
текущий runtime-энкодер сохраняется. Все изменения выпускаются через Git и CD.
На экране нужны конкретные основания, история закупок, товары и понятная сила
подтверждений. Общая плашка «Нужна проверка» для всех кандидатов не подходит.

## План

- [x] Проверить свободную RTX 5060 Ti и наличие локальных весов 4B.
- [x] Изучить внешний подход: обучение на retrieval-кандидатах, QuerySoftMax,
  расширение пула, история заказчика. Их метрики не сравнивать с нашими напрямую:
  временные окна, выборки и входные признаки отличаются.
- [x] Подготовить train top-200 на 4B, сохранив временное отсечение истории.
- [x] Обучить ранжировщик на кандидатах поиска, включая retrieval-признаки.
- [x] Сравнить loss/признаки на validation, отдельно считать попадание участников
  и победителя, не исключая отсутствующего в пуле победителя из знаменателя оценки.
- [x] Выбранную конфигурацию проверить на закрытом test; измерить задержку и память.
- [x] Подключить модель только при подтверждённом улучшении, оставить fallback.
- [x] Выпустить подготовленный импорт архивных оснований в ClickHouse из read-only prepared DuckDB.
- [x] Реализовать отображение опыта в категории, подтверждённые победы, товары, даты и архивный источник.
- [x] Показать силу оснований и объяснения без неподтверждённых процентов вероятности.
- [x] Проверить frontend, backend, e2e и выпустить через GitHub Actions.

Начальный кандидат: 4000 train-запросов, фиксированный validation из 1000
запросов seed=42, top-200, запрос 256 / карточка 512 токенов, локальный BF16 4B.
Для train используются только профили истории до 2024-06-01, для validation —
до 2024-12-01. Фактические ТРУ целевого лота не используются как признак запроса.
Итоговый test не используется для выбора настроек.

Основа для сравнения подходов:
[описание](https://github.com/brawler2011/rlthack/blob/5fe7e5ce0695382d7236b037cbe790f882943ec2/README.md#quality),
[обучение](https://github.com/brawler2011/rlthack/blob/5fe7e5ce0695382d7236b037cbe790f882943ec2/backend/scripts/05_train_ranker.py).
Реализация адаптируется к нашим контрактам и данным; код внешнего проекта в
репозиторий не переносится целиком. Результаты записываются в ml/EXPERIMENTS.md.

## Итог

Test: 1000 запросов, MRR 0.2007 → 0.2577; известный участник в top-10
41.8% → 53.6%. CI95 прироста MRR [+0.0431; +0.0707]. Принят
softmax_winner, 434 дерева. Индекс: 83961 карточка / 37175 поставщиков;
190509 архивных оснований в ClickHouse. 20/20 test top-10 рабочего адаптера
совпали с offline, баллы идентичны. Старые загрузки пересчитываются при смене
версии; live e2e подтвердил обновление трёх закупок и текстовые причины.
Действующий и локальный энкодеры — только 4B; подключение оформлено в Git,
подмен исходников контейнера нет. Результаты и ограничения — в README и
`ml/EXPERIMENTS.md`, агрегированные отчёты — `ml/reports/ranker-v2-*.json`.
