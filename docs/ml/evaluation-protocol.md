# Протокол оценки итоговой системы

Документ фиксирует, какая версия системы чему соответствует, какие отчёты
относятся к какому режиму и по каким критериям принимается новая оценка.
Составлен 2 октября 2026 года до новых измерений; критерии ниже нельзя менять
после того, как результаты D2/D3 станут известны.

## 1. Версии рабочего конвейера

Каждый сохранённый результат (`searches.payload`) несёт `pipeline`:

| Поле | Что фиксирует | Где задаётся |
| --- | --- | --- |
| `version` | версия правил подбора общего конвейера: `search-v2` | `SearchSettings.pipeline_version` |
| `channels` | каналы, ответившие на запрос | `SupplierMatcher` |
| `models` | версия модели канала, например `semantic` → SHA256 `ranker.cbm` | ответ ML-сервиса `pipeline.pipelineVersion` |
| `inputs` | поля, которые реально использованы моделью | `SearchPipeline` |
| `noveltySet` | версия набора ИНН архива для новизны | `archive_supplier_sets` |
| `contractVersion` | версия HTTP-контракта (`2`) | `controller/search/mapper.py` |

Артефакты, на которых держится канал `semantic` (вне Git, проверяются по
SHA256 при старте `search-api`):

| Артефакт | SHA256 / версия | Источник |
| --- | --- | --- |
| Модель CatBoost `softmax_winner`, 434 дерева | `cc79a0a0a751af3e602d149b3766df7e5c30f4f57a7b114b3f54bbbecd4ce49f` | `ml/reports/ranker-v2-test.json` |
| Векторы карточек, Qwen3-Embedding-4B, 2560 изм. | `78a94e50f0cb570fef0c06c5a7a04cc71aacdb3b23b8ebb75a5e226ab563adf3` | `ml/EXPERIMENTS.md`, RANK-004 |
| Карточки, 83961 шт., история до 2025-06-01 | `ae76fb5f817ca568966db8752176718388e3739ab4e77bcde8a7933eb34d51d4` | там же |
| Признаки | 22 наблюдаемых, список в `runtime.json` = `ranker/features.py:FEATURES` | проверка при загрузке |

Каналы `lexical` (каталог) и архивная история версий моделей не имеют: их
поведение определяется кодом и `pipeline.version`.

## 2. Какой отчёт к чему относится

| Отчёт | Выборка | Вход | Модель | Используется рабочим маршрутом |
| --- | --- | --- | --- | --- |
| `ranker-v2-validation.json` | validation, выбор модели | текст; дополнительно текст+заказчик/цена | три варианта CatBoost | нет, только для выбора |
| `ranker-v2-test.json`, `-test-full.json` | закрытый test, 1000 запросов, 979 с однозначным победителем | **текстовый режим** (основной), дополнительно режим с метаданными | `softmax_winner` | да, текстовый режим |
| `ranker-v2-serving-*.json` | 20 запросов | текст | та же | проверка совпадения офлайн/рабочего расчёта, не качество |
| `ranker-v2-runtime.json` | 1 искусственный запрос | текст | та же | замер старта и одного поиска, не p95 |

Рабочие маршруты:

- `POST /api/searches` и каждая закупка `POST /api/uploads` идут через один
  `SupplierSearchService`; канал `semantic` вызывает ML-сервис только в
  текстовом режиме. ИНН заказчика и НМЦК сохраняются, но в `inputs` не попадают.
- Поэтому в интерфейсе и презентации допустимо приводить только метрики
  текстового режима test: MRR победителя 0.2008 → 0.2577, Hit@10 победителя
  0.3453 → 0.4454 (n = 979, бутстреп ΔMRR CI95 [0.0431; 0.0707]).
  Метрики «с метаданными» (MRR 0.3400) к рабочей системе **не относятся**.
- Эти метрики измеряют только переранжирование исторического индекса. Они не
  включают каталог, новых поставщиков и проверку товаров — это задачи D2/D3.

## 3. Режимы входа

| Режим | Допустимый вход | Статус в рабочей системе |
| --- | --- | --- |
| text-only | название/предмет закупки, явные позиции | используется |
| text + заказчик/цена | плюс ИНН заказчика, НМЦК | модель обучена, рабочее применение не включено: нет признаков заказчика в runtime-артефактах |
| явные позиции | список позиций (`items`, origin `user`) | используется, позиции не смешиваются с выведенными |

Фактические ТРУ из архива в text-only поиск и его оценку не подставляются:
интерпретатор строит позиции только из текста запроса или явного списка.

## 4. Критерии приёмки (до измерений)

D2, полный поиск и ранжирование, на **новой** независимой выборке (test уже
открыт и использовался для принятия модели, повторно для выбора не применяется):

1. Выборка: 1000 процедур после 2025-06-01, не пересекающихся с test RANK-004,
   seed и SHA256 списка фиксируются до прогона.
2. Сравниваются: лексический baseline и итоговый конвейер `search-v2`
   (лексика + архив + semantic). Промах на этапе поиска — промах итога;
   ошибки и пустые ответы остаются в знаменателе.
3. Метрики: Hit@1/@10 и MRR победителя, Recall@10 участников, полнота пула,
   доля ошибок/пустых ответов, разрезы по категориям, длине запроса,
   многопозиционности и объёму истории. Бутстреп по процедурам, 2000 повторов.
4. Принятие: итог не хуже baseline по MRR победителя с CI95 нижней границей
   ≥ 0 и доля ошибок ≤ 1 %. Иначе фиксируется результат и ограничение.

Выборщик D2 исключает дату `history_before` включительно и сохраняет полный
список категорий каждого лота. В категории один многокатегорийный лот учитывается
в каждой подходящей группе, поэтому срезы по категориям могут пересекаться.

D3, новые поставщики: протокол в `ml/NEW_SUPPLIERS_REVIEW.md`.

## 5. Ограничения времени (утечка будущего)

- Исторические признаки ранжировщика строятся только по закупкам до
  `history_before` из manifest индекса (2025-06-01); импорт оснований
  отказывает при расхождении границы (`history_import.py`).
- Текущие сведения карточек (каталог, реестр, контакты, названия МСП) в
  признаки модели не передаются: запрос к ML-сервису содержит только текст и
  позиции (`tests/adapter/client/test_ml_service.py::test_model_request_carries_no_current_card_data`).
- Для D2 выборка должна быть позже `history_before`, иначе она не проводится.

## 6. Что не измерено

Качество каталога и новых поставщиков, итоговая полнота с учётом каталога,
скорость на рабочем объёме. Пока D2–D4 не выполнены, эти свойства не
заявляются ни в интерфейсе, ни в презентации.
